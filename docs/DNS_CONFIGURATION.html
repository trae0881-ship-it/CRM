Provider-specific values

DNS configuration

DNS targets are supplied by the actual hosting provider. Adometa creates an ownership TXT challenge but does not invent A, AAAA, CNAME, nameserver, or verification targets.

1. Find the correct DNS zone

  1. Identify the registrar or DNS provider authoritative for your domain.
  2. In the hosting project, add the exact root or www hostname and open its DNS instructions.
  3. Confirm whether the DNS zone is managed by the registrar, Hostinger, Cloudflare, or another nameserver provider. Edit records where the authoritative nameservers point.

2. Copy the records from the provider

The provider may request an apex address record, a www CNAME, or a nameserver change. Each provider and deployment can differ. Copy the hostname/name, type, value/target, and TTL from the provider screen; remove an existing conflicting record only after confirming the change plan.

Record typePurpose (general)Use this value
A / AAAAMaps a host to an IPv4 / IPv6 addressOnly the address displayed by your hosting provider
CNAMEAliases a subdomain to a provider hostnameOnly the target displayed for your project
TXTDomain ownership challengeThe exact name and value shown by Adometa for that hostname
NSDelegates a DNS zoneOnly the nameservers given by the provider

3. Add the Adometa TXT challenge

In the Domain management record, copy the displayed TXT name and challenge value into the authoritative DNS zone. The name is scoped to the hostname being verified. Do not reuse another hostname's challenge and do not publish secrets in a public ticket or screenshot.

The examples in this guide are about record types, not actual DNS targets. Never use sample IP addresses, domains, or values for production.

4. Wait and verify

DNS propagation is not instantaneous and cached results can differ between resolvers. Check the provider's DNS panel, then click Verify DNS and SSL in Adometa. If the TXT check passes but HTTPS fails, finish connecting the hostname and wait for the provider to issue its certificate.

Provider instructions

  • Hostinger: in the website/domain panel, use the DNS records shown for the selected site and plan.
  • Vercel: add the domain in the project settings and copy the generated configuration for that project.
  • Railway: attach the custom domain to the public service and use its generated DNS target and TLS status.

These are navigation hints only; current dashboard labels and exact values may change.
