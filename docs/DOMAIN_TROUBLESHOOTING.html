Domain troubleshooting

Use the actual verification state and provider diagnostics. A hostname must not be treated as active until DNS ownership and HTTPS certificate checks succeed.

Observed stateWhat to checkNext step
Pending DNSTXT name/value, authoritative nameservers, propagationCopy the current challenge again and add it at the authoritative DNS provider.
Verification failedLast verification time/error code, hostname spelling, DNS recordsFix the provider configuration, wait for propagation, and retry.
DNS verified / SSL pendingHost attachment, A/AAAA/CNAME target, certificate issuanceComplete hosting-provider domain setup and wait for TLS issuance.

DNS check fails

  1. Check which nameservers are authoritative for the domain.
  2. Confirm the TXT record is entered at the authoritative DNS provider, with the exact host/name and value.
  3. Check for quotes or provider-specific domain suffix behavior; follow that provider's input format.
  4. Wait for the record TTL and resolver caches, then retry from Domain management.
  5. If the status still fails, use the verification timestamp and safe error code shown in the admin UI when contacting support. Do not send credentials or tokens.

HTTPS probe fails

Confirm the domain is attached to the right hosting project, the provider target is correct, the app responds over HTTPS, and the certificate covers the exact hostname. The backend verification probe uses certificate validation; it does not bypass TLS errors. A temporary provider certificate error is a failed check, not an active state.

Unexpected redirect

Disable the host-level redirect temporarily, then verify the Adometa primary and redirect mode. Re-enable exactly one desired host-level rule. Check HTTP-to-HTTPS handling at the provider and ensure the canonical hostname itself is not configured to redirect back to the alternate host.

Roll back

Set the previous verified active domain as primary. Revert the provider redirect and Supabase Auth URL settings to the last working configuration. Keep DNS intact until login, recovery, invitations, and public routes are confirmed again.
