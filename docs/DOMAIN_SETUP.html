Platform administration

Domain setup

Use the platform domain page to register a hostname, complete the provider's DNS setup, and verify ownership and HTTPS before marking it active.

1. Add a hostname

  1. Sign in as a verified Super Admin.
  2. Open /saas/admin/domains from the platform navigation.
  3. Choose the hosting provider and enter one hostname at a time, such as a root hostname or www hostname. Do not enter a URL, path, port, or wildcard.
  4. Select Add domain. Copy the generated TXT name and value shown for that hostname.

2. Configure hosting and DNS

Add the hostname to your actual hosting provider first. Copy its displayed A, AAAA, CNAME, or nameserver instructions exactly. Add the separate Adometa ownership TXT record as shown in the admin page. Record types and targets differ by provider and deployment; no universal target is safe to assume.

Detailed DNS guide →Connection checklist →

3. Verify ownership and TLS

  1. Wait for the DNS provider's records to propagate.
  2. In Domain management, choose Verify DNS and SSL.
  3. The server checks the public TXT challenge and public address records, then makes an HTTPS request with normal certificate validation.
  4. Only the successful DNS and HTTPS checks can produce an Active status. A pending/error state is not evidence that the hostname is live.
The verification probe is not a guarantee of application availability for every browser, network, or route. Check the hostname yourself after activation.

4. Configure Supabase Auth manually

Changing the canonical domain in Adometa does not change Supabase project settings. In the Supabase Dashboard, open Authentication → URL Configuration and set the Site URL to the verified canonical HTTPS origin. Add the exact login/signup/recovery redirect URLs used by your application under the allowed redirect URLs.

https://YOUR_VERIFIED_HOSTNAME/
https://YOUR_VERIFIED_HOSTNAME/**
https://mxcqrxfmnvnkxifjssyn.supabase.co/rest/v1/

Replace the uppercase examples with real dashboard values. For OAuth providers, also update their provider-side callback configuration to the exact callback URL shown by Supabase. Never add a guessed hostname or wildcard more broadly than your security policy permits.

5. Select the canonical hostname

After the DNS and certificate check succeeds, select the hostname as primary. Add and verify the alternate root or www hostname separately if you need both. Choose the preferred redirect direction in Domain management and also configure the equivalent redirect at the hosting provider; browser-only redirects cannot run before the application loads.

6. Roll back safely

Keep the old hosting domain available during rollout. If the new hostname fails, change the primary hostname back to a verified active domain, restore the provider's previous redirect settings, and revert Supabase Site URL/allowed redirects to the last known working values. Do not remove the old DNS record until login, recovery, invitation, and public pages have been checked.

Where to find provider values

  • Hostinger: open the website/domain panel and follow the connection target displayed for the selected hosting plan.
  • Vercel: add the domain to the project and use the exact DNS records Vercel displays for that project.
  • Railway: add a custom domain to the public service and use its generated target and certificate instructions.

Panel labels can change. Trust the current provider dashboard, not copied examples.
