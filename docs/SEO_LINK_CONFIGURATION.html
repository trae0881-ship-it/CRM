SEO and link configuration

Public metadata and sitemap entries should use the verified canonical domain and only actual public indexable routes. Login, workspace, Super Admin, and protected API pages must remain excluded.

1. Public page metadata

For supported public pages, the application URL helper uses the selected canonical hostname for canonical link metadata, Open Graph and Twitter URL/title/description values, and WebSite structured data. It avoids indexing authenticated routes and private pages. Inspect the actual page source and browser head after deployment; do not assume a link inventory entry proves metadata is live.

2. Sitemap and robots endpoints

The server-side database API exposes:

GET /seo/sitemap.xml
GET /seo/robots.txt

The endpoints use the verified canonical domain and route registry. They are hosted by the database API service; they are not automatically available at the application root on static Hostinger hosting. Configure a hosting rewrite/proxy or a deployment publication step that maps the public root /sitemap.xml and /robots.txt to the correct server-generated content. Verify the actual response and correct Content-Type before submitting a sitemap to search engines.

Do not submit an API-hostname sitemap as the app's canonical sitemap unless it is intentionally the public origin. Do not list private dashboards, login sessions, admin paths, or protected APIs as indexable pages.

3. robots.txt policy

Disallow private route prefixes such as dashboard, login, and Super Admin pages from crawlers. A robots rule is not access control; authentication and backend authorization must still protect private data. Never include a sitemap URL until a public sitemap route is actually deployed and verified.

4. Verify after changing the primary domain

  1. Open each public page at the canonical HTTPS origin.
  2. Inspect the canonical link, meta description, Open Graph and Twitter tags, and structured data.
  3. Request the public sitemap and robots file over HTTPS and inspect their body, status, and content type.
  4. Confirm sitemap entries are absolute canonical URLs for public indexable routes only.
  5. Check alternate-host redirects and ensure no redirect loop.

5. Route inventory is not a health guarantee

The Super Admin link inventory includes actual registered routes and labels availability separately from live HTTP checks. Private API and integration callback links are restricted to Super Admin visibility. A successful HEAD/GET response does not test login, permission boundaries, or the real browser flow.
