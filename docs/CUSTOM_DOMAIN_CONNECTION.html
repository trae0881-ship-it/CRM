Custom domain connection

A domain is a hostname registered in your hosting provider and verified by Adometa. A root domain and its www hostname are separate DNS names and should be configured and checked separately.

1. Prepare both names

Decide which public URL should be canonical, for example a root name or its www subdomain. Confirm you can edit the DNS zone and add custom hostnames in the deployment project. Avoid migrating while authentication callbacks or provider webhooks are in active use.

2. Add root and www separately

  1. In /saas/admin/domains, add the root hostname without a scheme, such as the format example.test (illustrative only).
  2. Add the www hostname as a second record if it is needed.
  3. For each record, copy the exact TXT challenge, then configure the hosting provider's own DNS target.
  4. Use the Verify action on each record. Do not expect one successful hostname to verify the other.
Illustrative DNS shape only: a provider may request an apex A/AAAA record and a www CNAME, or may instruct you to use nameservers. Actual values are specific to your deployment and are not provided by this example.

3. Select a primary and redirect mode

After both needed hostnames show Active, choose the primary. Then choose one behavior: no hostname redirect, www to root, or root to www. Configure matching redirects in your hosting provider too. Do not configure conflicting rules at the DNS provider, host, and application layers.

4. Verify the complete user journey

  • Open the canonical address over HTTPS and inspect the certificate in a browser.
  • Open the alternate hostname and check its configured redirect once. Confirm it ends on the canonical hostname without looping.
  • Test public pages, login, signup confirmation, password recovery, and a real invitation flow with a test account.
  • Check Supabase Auth and OAuth provider allowlists manually.
  • Check that an unauthenticated visitor cannot access a dashboard or either Super Admin domain route.

5. Rollout and rollback

Keep the old app address and DNS configuration until all tests pass. If a check fails, revert the primary setting to the last verified hostname and undo only the matching hosting redirect. The domain screen's audit history records domain changes; it does not change DNS or Supabase settings.
